Experiment 1 — interrupt and steer (the core technique)

Type this prompt and press Enter:

refactor every function in app.py — add type hints, error handling, docstrings, and unit tests for each one

Claude will start reading the file, then begin editing. After you see the first Edit tool call fire, press Escape. Then type:

stop — only fix the divide function for now, just add the zero check, nothing else
What to observe: Claude doesn't restart. It already read app.py and that file content stays in context. It just pivots. You saved all the token cost of re-reading the file. This is the core value of steering — you get to course-correct without paying for a cold start.

Experiment 2 — adding context mid-loop (without interrupting)

Start a new session (/clear), then:

find all the bugs in app.py and list them

Claude will read the file. While it's reading (you'll see the Read tool call), just type in the terminal — Claude Code in interactive mode reads your input between tool calls. Send:

focus only on resource management issues, ignore logic bugs
What to observe: Claude finishes the Read tool call, then incorporates your mid-loop message into its next reasoning step. It narrows the bug list to just the unclosed file handle. The docs call this "it's a conversation" — you're not interrupting, you're adding to the loop.
